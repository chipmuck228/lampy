# 账号模型与兼容迁移（第一片）

基线 main `3e0c9e207febf068ae56e755db96ad03ba2641d0`。只实现服务端身份存储，保持现有 UI 与受控登录门控。本轮不开放 Apple 登录／绑定，不接邮件链接、Google、微信，不部署或上传 TestFlight。

## 模型

- `family_accounts.user_id` 是稳定 Lampy 账号；家庭、成员、分享、资料、会话继续引用它。
- 新 `family_login_identities` 把 `(provider, subject)` 映射到该账号。同一身份只属于一个账号；第一版同一账号每种 provider 最多一个身份。重复挂载同一身份幂等，跨账号占用或替换已绑定身份失败。
- 当前 provider 只有 `apple` 和 `controlled-password`。Apple subject 保持精确值；受控密码 subject 沿用既有规范化登录名。账号 email 是旧资料字段，不用于身份合并；同邮箱也不合并。
- 受控密码的哈希、enabled、disabled_at、operator_provisioned 仍在凭据表。身份表不存密码／Token，也不授予登录资格；原认证及受控开放校验保留。
- `attachLoginIdentity` 是事务内部持久化接口，没有 HTTP 路由。它只负责账号存在与身份唯一性，**不负责验证用户凭据**。下一片必须在有效会话、明确绑定意图和服务器验证 Apple 凭据后调用，不允许信任客户端传入 subject/userId。

## 迁移 28

1–27 原文不改。新建身份表与约束，并回填旧 Apple subject 和受控凭据登录名。保留 userId、密码哈希、停用状态、会话、昵称、家庭、媒体、分享及本机个人库；不重新注册，不清会话，不合并账号。

迁移用现有 BEGIN IMMEDIATE 原子机制，重复运行不重复回填。空身份、重复身份或孤立凭据会使迁移失败并回滚，不忽略损坏行。升级前先备份并在副本上迁移。

后续账号／凭据写入在同一事务同步新身份。Apple 查询走身份映射；旧列保留用于兼容创建逻辑。旧凭据认证继续走凭据表，不把身份存在当成密码或停用校验。

## 部署与回滚

本 PR 不操作公网库。批准部署后：停唯一服务，备份数据库及 WAL/SHM 与代码，先在副本演练，再用新代码执行既有 `npm run family-api:migrate`，确认 max(version)=28，启动匹配的新服务。旧会话应能继续读取原账号和家庭。

不要让 27 版服务在迁移后的库继续写新账号，它不会同步身份表。回滚需要停服务并恢复匹配的代码与数据库备份；不能只换回旧二进制并宣称安全。迁移后若已产生新写入，恢复旧备份会丢失这些写入，须先确定保全方案。

## 后续 Apple 片的前置规则

设置内明确绑定当前测试账号后，应保留家庭与昵称。未登录的 Apple 首次登录可创建新账号；已有身份回同一账号。冲突不自动合并。取消、后台、锁定、来源切换后的迟到回调无效；邀请返回仍需确认加入。本片没有实现这些新 UI 或服务器绑定命令，不把模型测试称为绑定端到端通过。

个人记录仍属于本机，与家庭账号切换独立。账号删除继续是公开创建账号的发布前置项。

后续实现见 [Apple 登录与明确关联](../apple-login-linking/README.md)；本文件保留 #107 当时范围，不能作为新入口已通过实页验收的证据。
