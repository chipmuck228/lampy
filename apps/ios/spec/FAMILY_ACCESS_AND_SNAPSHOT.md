# 家庭读取权限与快照（Phase 3A）

日期：2026-09-25。权限无法确认时取**最小授权**；媒体缺失与同步失败取**保全**（不删原 Moment、不伪造已读权）。本机缓存文件**不是**当前授权证明。

---

## 1. 读取权限矩阵

图例：

- **是**：现有设计已要求或可从「默认个人 + 明确分享 + 独立 Transmission」推出。
- **否**：现有设计禁止或可推出为禁止。
- **待决定**：无法从现有规格推出，实现不得自行假设。
- **当前仓库**：今日代码的实际行为（对照，不是目标）。

主体：

- **发送者**：Moment.ownerId 为本人的原记录。
- **仍是成员的家人**：对该家庭有有效 Membership。
- **已退出 / 被移除的前成员**。
- **从未加入的人**。

| 状态 | 发送者读自己的原 Moment | 现成员在家庭时间页读该分享 | 现成员读发送者未分享的私人 Moment | 前成员读家庭时间页 | 前成员读自己设备上已落盘的 Received Moment | 外人 |
| --- | --- | --- | --- | --- | --- | --- |
| 分享前 | 是 | 否 | 否 | 否 | 无此对象 | 否 |
| 分享成功且 Membership 有效 | 是 | 是（经有效 Transmission + 当前成员资格） | 否 | 否 | 视其是否曾接收 | 否 |
| 成员主动退出 | 是 | 否（当事人） | 否 | 否 | **待决定** | 否 |
| 成员被移除 | 是 | 否（当事人） | 否 | 否 | **待决定**（可与退出不同，但必须单独决定） | 否 |
| 分享撤回 | 是 | 否 | 否 | 否 | **待决定** | 否 |
| 离线（曾验证过授权，现无法向服务端确认） | 是（本机自己的数据） | **否（家庭页不得宣称当前授权）** | 否 | 否 | 可展示「上次收到的副本，授权未确认」，不得标成「家人空间仍有效」 | 否 |
| 权限无法确认（错误 / 过期会话） | 是（仅本人本地行） | 否 | 否 | 否 | 同上，最小授权 | 否 |
| 当前 iOS 仓库 | 是（本机全部个人记录） | 无家庭页 | 无 | 无 | 无 Received 写入 | 无账号 |

补充：

- 家庭管理员也不能读成员未分享的私人记录（产品指南 §16.2）。
- 「本机 SQLite 里还有一行」只证明磁盘上有数据，不证明 Membership 仍有效。
- 媒体文件还在，只证明文件未删，不证明仍可在家庭页展示。

## 2. 快照

### 2.1 现有领域已经说了什么

Received origin **必须**有（`domain/moment/moment.validator.js`、`spec/moment-invariants.md` #13）：

- `transmissionId`
- `originalMomentId`
- `snapshotRevision`（整数 ≥ 1）

接收者 Moment 的 `ownerId` 是接收者。这推出：家庭接收应形成**接收者自己的副本**，钉在某个 `revision`，而不是去改发送者那一行。

领域**没有**规定：快照正文存在哪张表、在发送时还是接收时固化、Asset 是复制还是引用。

### 2.2 本轮定义（实现必须遵守的方向）

**形成时机（推荐定义，共享领域未实现前不得写成已有能力）：**

1. 发送者确认分享 → 创建 Transmission，记录 `sourceMomentId` + `sourceRevision`（现有字段）。
2. 接收端在**授权仍有效**时物化 Received Moment：复制当时那一版的内容字段，`snapshotRevision = sourceRevision`。
3. 若网络确认前进程退出：只允许有可恢复的 Transmission / 接收草稿，不得先出现「已收到」家庭页条目。

发送当时是否就在发送者设备写一份「待投递快照包」：**待决定**（影响离线出站）。

**快照应包含的字段（与现有 Moment 可对齐的最小集）：**

| 包含 | 不包含 |
| --- | --- |
| `content.note` / `emotion` / `significance`（若有） | 发送者草稿未激活内容 |
| `time.*`（含精度；不得把接收时间写成 occurredAt） | 发送者 `accessSummary` 当作接收者权限 |
| `assetIds`（指向快照形成时的引用） | 未挂接的临时拍照/录音路径 |
| `origin` received 三件套 | 家庭成员列表、邀请令牌 |
| 接收者自己的 `id` / `ownerId` / `audit` | 发送者账号密钥 |

`context.people` 是否进入快照：**待决定**（可能含他人显示名）。

### 2.3 原 Moment 后续变化

`snapshotRevision` 的存在推出：**已物化的接收副本不自动跟随**发送者之后的 `revision`。

未决（必须先决定再写同步）：

- 发送者编辑后，家庭页是继续显示旧快照、提示「作者已更新」，还是需要一次新的 Transmission。
- 发送者删除/回收原 Moment 后，已物化快照是否仍可读。

在未决定前，禁止实现「打开家庭条目时静默拉取最新原文并覆盖接收副本」。

### 2.4 Asset 引用

| 方案 | 含义 | 风险 |
| --- | --- | --- |
| 复制到接收者设备 | 接收者有自己的 Asset 行与文件 | 撤回后文件仍在；存储变大 |
| 仅引用发送者云 key | 读时再授权下载 | V1 无云 key；离线与撤回更难 |

**待决定**。无论哪一种：

- 媒体缺失只降级该 Asset，不把 Received Moment 标成不存在（与个人闭环一致）。
- 不得把系统相册原片当成家庭授权对象。
- 同步失败不得删除已确认的本地快照正文。

## 3. 保全与最小授权

| 情况 | 必须 | 禁止 |
| --- | --- | --- |
| 权限无法确认 | 只展示本人所有权下的个人数据；家庭页进「授权未确认」 | 用上次成功的成员列表继续当现成员 |
| 媒体缺失 | 原位说明；Moment / 快照保留 | 当成分享失败而删 Transmission |
| 同步失败 | 保留本地个人数据与已提交的幂等意图 | 显示「家人已收到」 |
| 进程重启 | 按仓库恢复 Transmission / 草稿，重放必须幂等 | 再生成一条分享 |
| 乱序到达 | 以幂等键去重；旧快照不得覆盖更新的已确认快照，除非协议明确允许 | 后到的过期邀请重新打开已关闭成员资格（规则未定时先拒绝） |

离线家庭页文案只能说明「这台设备上上次留下的副本」或「还不能确认家庭范围」，不能写「家人正在看」。

---

## 4. 与 iOS 个人缓存的边界

iOS 今天的 SQLite / 文件是**个人本地真源**，不是家庭授权缓存。接入家庭后：

- 个人 `moments` / `assets` / `drafts` 语义不变。
- 家庭授权结果、Membership、Invitation 必须可单独失效。
- 不得把 `listRecent()` 的结果直接当成 FamilyTimelineViewModel。
