# 数据与上线策略

只规划，不跑迁移、不修改旧 SQL 或生产库。

## 追加迁移候选

当前服务端 schema 已到 16；实施时重新核对最新编号并追加，不能重写 1–16。解除每 user 单家庭唯一约束，改 active(userId,familyId) 唯一；加入家庭名称、访问策略版本、解散时间/截止时间、转交请求、邀请哈希与 claim、清理任务。迁移须保留现有成员 / 分享 / idempotency 数据，备份拷贝验证。

服务端事务保证 user 10 家庭上限、唯一创建者、单邀请 claim；多个进程 / 并发写不能依赖前端按钮禁用或进程内锁。旧单家庭 HTTP 路由不再作为多家庭默认目标；候选增加 GET /v1/me/families 与 familyId 明确的 leave / transfer / authored-shares 管理接口。实际接口定义在实施 PR 完成，不把本稿路径当已存在。

多设备会话是明确缺口：现 Apple 登录删其他会话。后续使用设备独立会话，单设备退出撤本次会话，账号安全撤销可全撤；测试账号关闭 / disable 仍撤所有对应测试会话。不得用 local-user 或假 token 模拟两个账号。

## 历史访问策略切换

旧 audience 与 joinedAt 限制不能仅客户端忽略。为家庭设版本：legacy 与 family-history-v2。旧家保留旧授权直到迁移验收和创建者明确确认“新加入成员可阅读仍有效历史分享”；未确认不扩大访问。新建测试家庭用 v2。

旧 audience 可保留作当时发送审计，v2 权限按当前 membership / family / share 状态统一裁定，包括列表、详情和媒体。既有邀请切换时撤销并重新生成，不能把明文旧 code 偷换成新安全模型。旧客户端不理解多家庭或策略时须拒绝新命令 / 提示升级，不能猜第一个家庭。整个切换需要服务端与客户端版本门控，入口仍关闭。

## 缓存、媒体与期限

键包含 userId / familyId / shareId / assetId；当前选中 family 不是异步操作的授权凭据。账号变化失效全部旧请求；成员变化隔离该 family，撤回隔离该 share；UI 先拒读，文件删除失败写待清理任务并重启重试。复用现 isolateFamily / isolateShare，不能退出 A 清掉 B。

下载途中资格变化，迟到 bytes 不得重新成为可读文件。媒体直链不能绕过分享读权；所有对应对象读取都核查引用及状态。服务端已注销关系不保证能远程抹去离线设备，App 下次确认时立即隔离；不能承诺收回截屏、设备外导出。

解散记录持久化清理任务，截止 dissolvedAt + 30 天。先拒读再异步清理；跨家庭复用对象仅在所有有效引用消失后删除，不能解散 A 误删 B。失败上传无分享引用也需回收策略，具体短期 TTL 在媒体实施切片决定，不能无限留存。
同一 share 撤回后服务端读权立刻停；物理媒体回收同样检查其他有效引用。个人原件和生活册引用不参与服务端家庭清理。

## 部署顺序

隔离拷贝备份 → 迁移及回滚演练 → API 版本门控 → 隔离账号联调 → 受控公网验收 → 注册/UGC/付费前置项审查 → 单独批准开放。
回滚恢复入口关闭，禁止旧客户端扩大授权；不可简单回滚已采用多家庭的数据为单家庭约束。生产 family.yunpura.com 版本本轮未验证。
