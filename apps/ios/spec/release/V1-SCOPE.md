# Lampy 1.0.0 发布基线

本 PR 是第一步：固定范围与构建配置。配置可生成候选工程，不代表已满足上架条件。

| 范围 | 1.0.0 行为 |
| --- | --- |
| 个人记录 | 本机文字、照片、每段最多 1 分钟声音；已有长录音继续播放 |
| 回看 | 时间阅读、弹出日历、每日记录数量、照片与声音 |
| 个人生活册 | 创建、编辑、整理、连续阅读、素纸／手作与纸页预览 |

| 家庭生活册 | 创建者编辑整理；成员阅读；素纸／手作、连续阅读及纸页预览 |
| 本机保护 | 解锁保护、后台遮挡、声音中断 |

## Apple 与后续邮箱

1.0.0 先只使用 Apple 注册／登录。私人记录无须登录、默认本机保存；主动分享到家庭的内容才进入家庭服务。

身份以 Lampy 内部用户 ID 为准，Apple 身份以服务端验证的 subject 关联，不以邮箱相同推断为同一人。保留 Apple 隐藏邮箱用户正常使用家庭的能力。

以后接入 Resend 作为验证码投递服务：已登录用户主动发起邮箱绑定，必要时重新验证身份，再验证目标邮箱。验证码的有效期、单次使用、尝试次数和发送频率由服务端控制。绑定到原 Lampy ID，不新建家庭身份。若邮箱已属于另一账号，拒绝自动合并并走独立处理流程。不能只凭邮箱相同自动关联，也不能把 Apple 中继邮箱当成用户真实邮箱。

本阶段不新增 Resend SDK、邮箱绑定表或未启用的身份接口；在正式实现时再设计迁移与解绑。

Lampy 不承诺云备份或异常恢复；成品制作和未来用户自选存储不是 1.0.0 功能。关闭导出期间，帮助和注销说明不得引导用户使用尚不存在的导出入口。

## 构建

独立 profile：`appstore-v1`。固定版本 `1.0.0`，要求显式正整数 build number。预设正式家庭 API 为 `https://family.yunpura.com`；这是配置目标，未证明生产服务部署完成。

在 Mac 的仓库 `apps/ios` 中：

```sh
printf '请输入新的 build number：'
read -r LAMPY_BUILD_NUMBER
export LAMPY_BUILD_NUMBER
export LAMPY_ARCHIVE_OUT="$HOME/WeChatProjects/lampy-v1-artifacts/$LAMPY_BUILD_NUMBER"
bash scripts/release-archive.sh --appstore-v1 --prepare
open ios/Lampy.xcworkspace
```

原生目录已存在时脚本会停下以免覆盖本地修改；确认可替换后可设置 `LAMPY_ALLOW_PREBUILD_CLEAN=1`，脚本先备份。准备过程清除继承的付费／测试环境，禁用 dotenv，并将完整非敏感配置写入 Xcode 环境文件。旧的个人默认配置与家庭内部测试配置保持独立。

需要本机归档与检查时：

```sh
bash scripts/release-archive.sh --appstore-v1
bash scripts/release-archive.sh --appstore-v1 --inspect "$LAMPY_ARCHIVE_OUT/Lampy.xcarchive"
```

上述命令不上传。静态配置或归档检查通过不等于页面验收或审核就绪。
