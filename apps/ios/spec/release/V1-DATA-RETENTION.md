# 最小数据保留方案

状态：2026-10-21 实现提案，不是生产承诺。新增期限是产品候选值，不是法定统一期限；没有自动部署删除任务。原则是减少家庭服务非必要数据，不新增用户备份／恢复系统。

| 对象 | 当前行为 | 建议目标／触发点 |
| --- | --- | --- |
| 私人记录／个人册 | 本机，账号删除不清私人库 | 保持，无私人库托管或恢复承诺 |
| 有效家庭分享／家庭册 | 服务保存必要内容与引用 | 有效期间保存，不固定 30 天删除 |
| 撤回分享 | 停止后续授权，snapshot 和文件可能保留 | 建议撤回满 30 天后清除正文与无其他有效引用媒体；不是恢复窗口，不提供恢复入口 |
| 删除账号 | 行删除，媒体尝试删除／失败重试 | 保持即时失效，监控队列；不因审计而保留原文 |
| 解散家庭 | 30 天 deadline，定时有限批次重试 | 保持；册子、快照、邀请、无其他有效引用媒体及相关处理记录清理 |
| Apple challenge | 5 分钟有效，请求时 prune | 定时清过期行，不只依赖再次登录 |
| 到期会话 | 授权失效，行未必删除 | 建议到期 24 小时后清除，不能影响有效会话 |
| IP／邀请／举报限流桶 | 窗口过期但仍可留行 | 建议各自窗口结束 24 小时后删除；不能提早清桶绕过限流 |
| 屏蔽关系 | 至解除或相关账号删除 | 保持，不随举报期限误清 |
| 举报说明／回执 | 账号删除／解散清理，无统一定时上限 | 建议处理完结后 180 天清；先增加明确 closedAt，不拿 createdAt 猜结案 |
| 待处理举报 | 无统一期限 | 超过 30 天运营提醒，不自动结案；最终期限随安全流程定稿 |
| 有效下架状态 | 持续阻止分享阅读 | 原分享存在时必须保留；不能清审计后复活内容 |
| 账号分享限制 | 至解除或账号删除 | 有效处罚不能跟历史记录一起过期 |
| 业务处理历史 | 无统一上限，含原因 | 建议 180 天，保留有效限制的最小状态；先修正按举报推导作者提示的依赖 |
| Admin 访问审计 | 已实现启动／小时清理 30 天 | 保持；引用不等于匿名，删除账号后不应保留不必要关联 |
| 应用／代理日志 | 实际生产配置待复核 | 不新增含 token、邀请秘密、正文、密码或媒体的请求日志 |
| journald／rsyslog | 未统一上限，rsyslog 四轮周轮转 | 建议 7 天加容量上限，先确认主机其他服务，不盲改全机 |
| 运维数据库副本／云快照 | 存量与期限未知 | 建议限运维、受限访问、最长 7 天滚动；清单确认前不批量删，不声称没有副本 |

举报结案、业务审计和有效处罚分开管理。作者限制／解除不自动证明举报结案。不得因回执过期恢复已下架内容、已受限账号或删除仍引用的媒体。

## 实施顺序

1. 只读盘点过期会话、限流、撤回、清理队列、两类审计；只输出聚合量，不取私人内容。
2. 先清过期 challenge、到期会话、已过窗口桶；测试边界、回滚和正常授权。
3. 撤回清理覆盖快照、幂等响应、册子封面、媒体复用、旧分享路径。先退休元数据，再删无活引用文件，失败持久重试；必要撤回状态不含原文，防止旧请求复活。
4. 为结案时间做迁移；报告、处理历史、有效处罚各有独立规则。不能直接删全部超过 180 天的 report 或 moderation 行。
5. 主机日志与运维副本单独落地；复核后再把实际执行期限写入公开政策。

SQLite DELETE、WAL checkpoint、文件删除和介质安全擦除不是一回事。不在在线库随意 VACUUM，也不因此宣称云快照旧字节已消失。对用户解释访问失效、服务端清理和外部副本边界，不承诺未实现的即时永久擦除。

以上是待审阅的最小方案，本 PR 不改变任何存量数据或清理任务。
