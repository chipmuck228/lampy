# 家庭共享安全：下一实施片

状态：设计及接入清单，尚未实现举报、屏蔽或运营处理接口。不得按此文档宣称功能可用。

基线：main 8cc9153（#124）。#124 的 8 项客户端验收已由用户在 iPhone 17 Pro / iOS 26.3.1 真机通过；服务器清理 timer 仍未部署验收。付费、个人及家庭导出继续关闭。

## 范围与规则

只处理主动上传的家庭分享，不扫描或上传未分享的私人记录。举报和屏蔽分开：举报不会自动删除他人内容；屏蔽只改变当前读者看到的内容，不移除家庭成员或转交 creator。

- 举报：仅当前具备该分享阅读资格的账号可提交，枚举原因加可选短说明；服务器产生回执。重复提交采用请求幂等键并限流，不能用任意 share ID 探测其他家庭。仅返回本人回执，不泄露举报者给被举报者。
- 屏蔽：关系属于当前账号对目标账号，跨本人所属家庭生效；禁止屏蔽自己，可解除。不改变其他成员视图，也不影响私人本机源记录。成员列表保留完成离开、移除或转交所需身份操作；内容视图隐藏目标作者的分享。
- 运营隐藏：独立于分享者主动撤回的状态，管理员可限制家庭服务中的内容；不覆写作者本机记录，不让普通成员调用运营接口。所有处理须留最小审计记录。
- 举报资料保留期限、公开支持渠道和运营处理人尚需确认；不得虚构邮箱或响应时限。未完成真实运营接收与处理演练，不标记完整上线闭环。

## 已核对的接入位置

| 层 | 接入及必须满足的约束 |
| --- | --- |
| 数据 | `src/family-api/schema.ts`、`repository.ts`、内存及 SQLite repository：新增举报、屏蔽、处理状态和读者安全版本；迁移独立递增，不修改旧迁移 |
| 分享 | `share-commands.ts`：家庭列表、详情及媒体授权统一计算当前读者可见性；同一媒体被多条分享引用时，必须至少有一条当前仍可读引用 |
| 册子 | `family-album-commands.ts`：list/read/validate 均使用当前读者过滤；手选和自动封面不可引用隐藏作者；屏蔽版本进入 validation，不能只对列表做本地隐藏 |
| HTTP | `http.ts`：所有读写绑定认证账号和当前家庭资格；变更有幂等及输入上限；错误不能泄露其他家庭内容存在性 |
| 客户端 | 家庭记录详情增加举报和屏蔽入口及确认；设置提供已屏蔽用户和解除操作；成功后立即清掉受影响视图并重新核验 |
| 缓存与声音 | `infrastructure/family-receive-cache.ts` 及媒体缓存：按账号隔离，安全版本变化清理受影响内容、图片与音频，停止正在播放的被隐藏声音；迟到请求不能重新写入旧内容 |
| 删除与清理 | 新关系纳入账号物理删除；保留审计资料的范围与期限先明确，避免旧身份再次注册恢复旧关系或内容 |
| 运营 | 有权限隔离的本机管理命令，默认只读查看回执，变更操作显式指定对象、原因并审计；不向公网开放无保护管理入口 |

## 实施顺序

1. 仓储、迁移、举报命令及读者可见性规则；内存与 SQLite 一致性及跨家庭隔离测试。
2. 屏蔽及运营隐藏接入分享、册子、媒体授权和 validation；针对旧令牌、共享媒体引用及 creator 过滤差异做回归。
3. App 操作入口、缓存失效与播放停止；中文／英文文案。
4. 明确支持渠道、运营接收与处置演练；再做云端迁移、双账号真机验收。

不能只交付前端隐藏或孤立举报表，就把本片标记为实现完成。

## 验收矩阵

- 普通成员可举报当前可读记录并取得回执；重复请求不制造重复举报；陌生家庭 ID、过期成员和未登录请求被拒绝。
- A 屏蔽 B 后，A 的家庭列表、详情、册子正文、封面、纸页和媒体均无 B 内容；C 仍能阅读 B。A 不能借旧媒体 URL 重新取得内容。
- A 是 creator 时仍可管理册名、开篇、顺序等元数据，不因此把隐藏作者内容返回 A；B 的私人源记录不受影响。
- 屏蔽发生在加载或播放期间，不闪回旧照片，不继续播放；切换账号及重启不能恢复旧缓存。
- 解除屏蔽后重新联网核验才恢复，已撤回或运营隐藏的记录不能恢复。
- 运营处理有审计、拒绝普通账号，并使全部有资格读者的旧内容核验失效；处理不影响其他记录。
- 账号删除清除新增账号关系；同 Apple 身份重新注册不会恢复旧举报／屏蔽身份。
- 购买、导出和打印入口保持关闭；私人新增、回看、册子和一分钟录音不回归。
