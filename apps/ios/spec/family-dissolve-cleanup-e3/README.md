# Phase E3 — 解散与30天清理

基线：最新 main `4164ad1060e33311e513603f0cefe1accd52cc6e`（#98 普通 merge）。独立分支 `ios/family-dissolve-cleanup-e3`。不合并、不部署、不上传 TestFlight，家庭 Release 开关与 identityLoopAccepted 不改。

## 用户操作

单列家庭 → 选中一家 → 原位展开「家庭成员」→ 底部低强调「解散家庭」。仅创建者可见。确认框解释全员失去分享访问、邀请／待移交失效、无法恢复、30天后清理家庭副本；个人原件和生活册不动。取消不发请求，确认绑定本次查看的 familyId 与 membershipId。重复确认复用提交锁；账号、失焦、后台、保护或选择范围变化后的确认失效。

成功刷新家庭列表并反馈「这个家庭已解散，个人记录还在。」；失败可重新读取与确认。解散已在服务器完成而响应丢失时，同一原创建者可安全重试；不会重设清理期限。成员刷新／重新进入时重新鉴权，家庭消失、旧分享和缓存声音不可再读取。没有服务器推送，不承诺另一台设备在零网络请求的静止页面瞬间变化。

## 服务端

- `POST /v2/families/:id/dissolve` 要求 membershipId；复核当前创建者与确切成员资格。v1兼容入口使用同一后端解散事务。
- 同一事务标记 dissolved、保存 dissolvedAt / dissolvedBy / cleanupDeadline=dissolvedAt+30×24h，移除有效成员，撤销所有待用邀请、终止待移交。所有家庭分享读路径重新校验 active 家庭。
- 通用 owner 媒体读取不能借旧 objectId 绕过解散：仅被已解散家庭引用的对象拒读；跨有效家庭复用仍可用，未分享的上传保持原 owner 规则。
- 家庭生命周期与正文只在服务端家庭 SQLite 内处理；没有个人 Moment、个人媒体或生活册的删除入口。
- 客户端当前解散路径只隔离原账号／原家庭接收缓存，立即作废其迟到阅读；缓存文件删除失败沿用现有 recoverDisk 待清理机制。

## 清理任务

`npm run family-api:cleanup`：必须明确设置已有 `LAMPY_FAMILY_DATABASE_PATH` 与 `LAMPY_FAMILY_MEDIA_PATH`，数据库已迁移到23。命令不新建数据库、不自动迁移、不接受时间覆盖参数；采用实际服务端时钟，每次最多20家。

1. SQLite BEGIN IMMEDIATE 复核到期家庭，并持久化文件清单。排除任何仍有其他有效家庭 active 分享引用的对象。
2. 同一事务移除家庭快照与含快照的幂等响应、邀请、移交、成员历史；清空家庭名；仅保留生命周期／最小解散重试审计，以及不含名称的创建请求 tombstone（旧创建重试不能生成新家庭）。退役媒体元数据及对应上传响应，写 snapshots_purged_at。
3. 事务提交后删文件。每个文件的错误、尝试数持久化；失败不标 cleaned_at。共用文件通过依赖表绑定每个待清理家庭，不能A删失败却宣称B已完整清理。
4. 成功写 completed_at / cleaned_at。再次执行安全；文件已删但结果未写入时可再次删。删除失败返回非零退出，作调度报警信号，不吞错误。

上传复用的文件恢复重新检查元数据并持有同一 SQLite 写锁；清理退役后，迟到恢复不能复活文件。通用媒体鉴权与读文件也在同一事务里串行执行。

**尚未配置生产调度或告警接收端。** 正式部署时需给该命令配置定时运行（建议至少每小时），监控非零退出、到期未完成任务与磁盘错误；失败可在同一路径上重试。此PR不操作生产。这里仅回收解散家庭关联对象，不改变从未分享上传的全局TTL政策。

## 隔离验收

先备份隔离库，执行现有 `npm run family-api:migrate` 至23，再用本分支重启隔离8787 API。UI仅JS改动，可连本分支Metro后Reload，无新增原生模块。不要重置个人库或Liuz17。

两模拟器：A创建、B加入，分享文字／图片／声音；A取消解散无变化，再确认；B刷新家庭／旧内容，邀请和待移交均不可用；A其他家庭、两边个人记录与生活册还在。随后测试重复确认、停止8787后的失败／恢复重试、保护遮挡。真实30天等待不必要：到期与失败恢复由注入时钟的隔离SQL／文件测试验证；不要手改正在使用的库或生产时间。
