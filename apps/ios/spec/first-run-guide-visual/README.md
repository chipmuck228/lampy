## 动画

Reduce Motion 分为 pending / 开启 / 关闭 / 查询失败，不用初始 true 同时表示「尚未查询」和「用户开启」。普通模式下目标照片与文案第一帧就是入场初态（opacity 0），不能完整显示一次再归零。查询超过约 800ms 仍无结果则按失败，直接完整显示，避免无限透明。

不能只因 index 改变就开始淡入。准备进入某屏与该屏已进入视口分开；点继续、上一屏、上滑翻页同一套入场资格。目标分页位置确认、AppState 为 active、Reduce Motion 关闭后，才播放照片 500ms 淡入和晚约 100ms 开始的文案块 450ms 淡入。第一屏还要等启动遮挡退场：布局和图片／字体就绪或失败兜底后，普通模式仍保持 opacity 0，再请求现有原生 SplashScreen 退场；收到完成信号并经过下一次绘制机会后才开始上述淡入。首次引导时 Gate 替换 Stack，JS 品牌层不会挂上；若品牌层实际盖着，也要等它离开。hideAsync 与 4s 兜底走同一条退场，不靠猜测等待。退场失败或超时按已离开处理，避免无限遮挡或无限透明。已有用户的启动与本机保护不变。无动画定位不依赖 momentum 回调。每次入场有独立序号；旧图片事件、滚动结束、定时器、迟到退场回调不能启动或覆盖新屏。切后台取消并恢复完整显示，回前台不自动重播。 Reduce Motion 开启或查询失败时内容直接完整显示，正常请求退场，不强制淡入。

字体加载完成或失败后锁定字面，避免 Songti 与 Noto 闪动。照片失败仍显示文案和操作。操作按钮不被动画阻塞。

旧隔离视频 `type-fade.mp4` 记为环境记录 A。环境记录 B 保留第二、第三屏可感知淡入。第一屏启动交接见 [`WALK.md`](./WALK.md) 环境记录 C：遮挡退场后才看到照片淡入、文案块更晚淡入。

分页宽高来自 SafeArea 内实际容器测量，正文列和照片只从该尺寸算一次 gutter。三屏按屏幕 ID 记住正文视口／内容高度；切屏不丢测量。窗口尺寸变化才失效并重测；未测完不当成“正文不需要滚动”。尺寸变化后当前页对齐对应分页位置。
