# 家庭成员昵称与头像墙：第二阶段

从最新main（#100普通合并 `8bb6bfbd0cbec1b48b836288da8695ebefb64a4e`）独立开分支，不在邮箱第一阶段分支续写。

## 范围

家庭卡片内展开「家庭成员」后呈现三列可换行的系统头像墙，昵称、13pt角色信息，不显示加入日期/邮箱。昵称完整换行，不靠缩字隐藏。无昵称的旧账号保留原「你／创建者／成员 N」回落。当前账号有昵称时角色附「你」；同昵称成员的辅助行使用成员序号，确认操作也带该说明，身份不由昵称决定。

创建者仅能点选其他普通成员。选中头像以sage细边标记，头像墙下出现所属成员昵称与横排「移交／移除」≥48pt操作；再点收起、选另一成员切换。保留已有确认框、requestId提交锁、待接受转交、撤销/接受、离开、解散和暂停声音。用户权限始终按userId/membershipId，不允许成员管理或创建者操作自己。换familyId会清旧阅读资格、成员和确认框资格。

GET /v2/families/:id/members在现有鉴权事务里读取当前有效成员的profile，新增可选nickname和avatar:'system'字段；不改变其他FamilyView接口或开放全局用户查询。用户不在该家、已离开/被移除、家庭解散时不可读。改昵称后重新展开成员会读取最新值。旧API没有这些字段仍能展示回落，不额外请求每个成员资料。

复用迁移26，不增加迁移/原生依赖。默认家庭入口与受控注册仍关闭。未实现分享作者昵称、头像上传、电话、付费、公网服务或真实双机Phase F。

## 走查

沿用隔离API路径与客户端开关，拉取分支后重启API+Metro，无需仅为此改动重建Dev Client。已迁移26的库不需要新迁移；旧库先停服务备份并执行family-api:migrate。Metro用IPv4 LAN，避免旧Dev Client IPv6网络检查器崩溃。

两账号加入同一家，修改各自昵称，展开成员：系统头像、昵称、角色、自己标识。关闭再展开刷新昵称。旧tester账号没有昵称仍可辨认。相同昵称按成员序号辨认，但移交/移除必须针对选中的membership。

先取消再确认移交/移除；成员不可管理；目录换家/离开页面/后台认证后旧确认不提交。断网重试、保护遮挡、个人记录/声音/生活册不变。短屏/横屏/iPad/中文英文/VoiceOver需要实页；自动化不代替设备。
