# 照片显现：原则（冻结）

本页冻结「最近」照片显现的设计语言。实现必须遵守，不得用更强的入场效果替换。

不改现有设计 token。不定义颜色或字体。不引入新的视觉组件体系。

---

## 1. 禁止强动画

明确禁止：

- scale 放大
- bounce
- spring 弹跳
- 卡片展开
- 从底部飞入
- blur 到 clear
- parallax
- 自动播放式展示

原因：这些会让用户觉得「应用在展示内容」，而不是「用户重新看到生活」。

显现必须轻微、克制、一次性。

---

## 2. 推荐显现方式

进入视口后：

| 量 | 值 |
| --- | --- |
| opacity | `0.85` → `1` |
| translateY | `8pt` → `0` |
| duration | `600–800ms` |
| curve | ease-out |

要求：

- 轻微
- 克制
- 一次性

不要再加第二段动画（例如结束再轻微回弹）。Reduce Motion 见 [`interaction-states.md`](./interaction-states.md)，不走这张表。

位移只用垂直 `8pt`。不要水平滑入，不要缩放。

---

## 3. 图片不是隐藏后出现

禁止：完全透明（opacity `0`）再突然出现。

原因：不要产生加载感。

初始状态：照片**已经存在**，只是还没被完全注意。所以起点是略低的不透明度加极小的下移，而不是空白处弹出一张图。

加载中的占位、解码失败、缺失说明**不是** Photo Reveal。那些沿用现网中性失败，不要套显现动画假装照片来了。

---

## 4. 多照片规则

同一条记录仍是：

文字 → 照片 1 → 照片 2 →（可能还有第 3 张）→ 声音 → 感受

每张照片**独立**显现。

不要：进入该条记录后一次播完全部照片。

用户还没滚到的后一张，保持 `not-seen`。前一张已 `revealed` 不影响后一张。

组带（若实现时仍存在并排两张）按**各自进入视口**计，不要整带一起播。

---

## 5. 与阅读的关系

动画触发：**用户滚动阅读**，照片进入视口。

不是：页面加载。

用户没有读到那里：不主动播放。

打开「最近」、下拉刷新、从详情返回而该照片仍在屏上：已 `revealed` 的不再播；仍在屏上但从未显现过的（例如 Reduce Motion 关闭后的新会话）只在这次进入视口时显现一次。

不要用定时器在首屏自动轮播照片。
