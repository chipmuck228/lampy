# 阶段 B：账号与多家庭基础

设计依据：../family-invite-share-design/。基线 main 为 #92 普通 merge `8d759d09e3b5b3056a2374d3c68954e776745dd9`。

## 已实现

- 复用真实 Apple identity / Keychain 与受控测试账号。每次登录保存独立会话，不再踢掉同账号其他设备；退出只撤本 token。测试账号 disable / 开关关闭的撤销规则保留。
- `GET /v2/me/families`：当前有效家庭的 ID、名称、本人角色、成员数和 limit=10。
- `POST /v2/families`：需要 `name` 和 Idempotency-Key；名称去首尾空白，1–40 Unicode scalar，拒绝控制字符。账号范围内同 intent 重试不重复创建，换名称复用 key 拒绝。
- SQLite 追加 17–19：家庭名称；active(user,family) 唯一及 active creator 唯一；10 家庭 insert/update 触发器。命令事务 BEGIN IMMEDIATE 在跨连接竞争时保证上限。新迁移自身事务化，失败不能留下半替换索引。未修改迁移 1–16。
- `/family` 使用受既有开关控制的列表与创建页，暖纸色、现有 SettingsPage / LifeText、48pt 操作；可选择家庭。刷新先藏旧数据；失败不是空库。选择仅保存在进程内，不代表授权，不自动选择第一家。
- 请求绑定账号 userId/token；页面失焦、锁定使创建资格失效，未发出的写入不继续。已发出的明确创建不能被客户端远程撤销；迟到结果不改新页。网络未知时保留同名称/intent 重试，稳定 key 即使 pending 记录已移除也不改变。
- 旧单家庭读取/退出遇到多个有效家庭返回 FAMILY_SELECTION_REQUIRED，不猜目标。Account 状态保留为已登录，旧分享路径遇歧义拒绝。

## 明确边界

家庭入口与 Release API/诊断配置未改，identityLoopAccepted 未改。新页不提供旧邀请码输入、邀请、分享、成员移除/退出/转交或解散按钮，等待 C–E；现后端旧操作仅保留兼容与隔离测试。

B 的选择目前只用于列表页当前范围，尚未接 D 的内容读取/分享目标，不声称已经实现家庭内容切换。新家庭仍沿用旧分享读权，不启用 family-history-v2；历史访问策略、哈希邀请、网页/AASA、账号删除、手机号/SMS、收费未实现。

一账号创建并加入多个家庭的数据能力已具备；旧 v1 接受接口依旧只支持无其他家庭的受控加入，不能当成新版多家庭邀请闭环。C 再实现确认加入的新版协议。数据库触发器已覆盖任何后续写入的合计上限。

将来部署须停旧服务，再备份/迁移并升级全部服务实例，不能让旧二进制在解除单家庭约束后仍运行。已有多家庭数据后不得直接恢复旧唯一索引；回滚先关闭入口并保留新数据。

本轮不部署 family.yunpura.com、不跑生产迁移、不创建生产测试账号、不上传 TestFlight。

## 实页验收方法（尚未做）

使用可丢弃本机/私网 HTTPS 服务和隔离家庭 SQLite，先备份并迁移至 19；不要连接生产库。测试账号仅在隔离服务创建/启用。个人库不清理。

只在测试构建明确设置 FAMILY_ENTRY_OPEN 与安全 API URL；账号入口沿用已有开发诊断/账户页。不提交本机 env；验收后恢复关闭。发布构建继续用入库 .env.production。

1. 未设置入口开关或直接深链 /family：只有敬请期待，不请求家庭。
2. 两账号：各自创建两个有名字的家庭；列表/选择不串，网络失败不画成空库。
3. 同账号两设备登录：各能读列表；退出 A，B 仍有效。杀进程恢复 Keychain。
4. 同一创建未知结果重试只产生一家；名称只读直到结果明确。超 10 家庭拒绝。
5. 创建中失焦/后台锁定，迟到结果不回填新页面；认证期间名称和列表不露。
6. 中英文、键盘、短屏/横屏/iPad/VoiceOver；个人最近/回看/录音/生活册回归。
