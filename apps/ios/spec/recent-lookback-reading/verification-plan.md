## 0. 什么能记 PASS

三种证据分开写，不能互相顶替。

| 写法 | 可以 | 不可以 |
| --- | --- | --- |
| **自动化 PASS** | Jest / tsc / lint / `git diff --check` 在写明的 SHA 上跑过 | 用来证明页面长什么样、声音、焦点、手势 |
| **模拟器 PASS** | 在写明的模拟器机型 / 系统上**实际点过、听过、滑过** | 只打开 storyboard 或看截图；**不能**写成「真机 PASS」 |
| **真机 PASS** | 在写明的物理设备上实际操作 | 模拟器结果、静态稿、Jest |
| **NOT VERIFIED** | 还没在该层做过 | — |

禁止：

- 把 `storyboard.html`、README、结构稿当成任何一种运行 PASS。
- 把模拟器实际操作写成真机 PASS。
- 把截图或录屏单独当成 PASS；它们只附在对应层的走查下面。
- 没做的项留空或写「应该可以」。标 `NOT VERIFIED`。

每份实现 PR 写实际运行 SHA。命令失败要对照基线 `d5c02386ebd335948f172b487df157390f3a3d9c` 定性，不能只因为「这文件没改」就称既有。

## 1. 每个实现 PR 的命令

在 `apps/ios`：

1. `npx tsc --noEmit`
2. 相关 Jest，再全量 Jest
3. 改动文件 lint
4. `git diff --check`

阶段 A 自身：设计文件不进 TypeScript。命令只证明本 PR 没有改运行代码。页面项全部 `NOT VERIFIED`。

## 5. 记录格式（B / C 用）

```
SHA:
命令: tsc / Jest 相关 / Jest 全量 / lint / diff --check
自动化: PASS | FAIL | NOT VERIFIED
模拟器: 机型 / 系统 / 模拟器 PASS 或 NOT VERIFIED + 缺哪条
        （此处禁止写「真机 PASS」）
真机: 机型 / 系统 / 真机 PASS 或 NOT VERIFIED + 缺哪条
夹具安装: 可丢弃包 id（不是 Liuz17）
证据: 静态稿未当作运行证据
```
