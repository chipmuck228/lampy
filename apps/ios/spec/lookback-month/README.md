# 回看月页：轻量月历

> 范围：只改 `apps/ios` 回看**月**页的展示层。年页、日页、详情、家庭、留下、最近不在本轮。
> 依据：`LAMPY_APP_PRODUCT_DESIGN_GUIDE.md` §4.2、§10.4 月、§12.6、§13.2。
> 基线：`origin/main` @ `ea7a281`（含 #20 / #21 / #22 / #23）。独立分支，不改 Recent / Leave。

对照页：`storyboard.html`。下列帧用真实日历结构说话，不用连续天数、完成率、红色空缺或打卡热力图。

## 改前

月页把 1…月末排成近似等权的日期项。有记录的日期标「有N条记录」并画密度带；没有记录的日期仍是可点按钮，只是文案为「安静」。

问题：

1. 日期不占星期位置，月初月末看不出是哪一周。
2. 安静日期与有记录日期同样可点，容易误进空日页。
3. 密度带按当月最大值拉长，接近热力图。
4. 超大字号下仍想塞进一排等权项，日期和「有N条」挤在一起。

## 改后

| 规则 | 做法 |
| --- | --- |
| 周位置 | 周一为一周之首。真实公历日放进对应格子；月初、月末用空白垫格，垫格不是日期。 |
| 安静日期 | 低强调数字，不可点，不进日页。 |
| 有记录 | 墨色日期 + 克制圆点（只表示「这里有留下」，不随条数变大变红）。点进原日页。 |
| 可读入口 | 月历下方「有记录的日子」列出 `9月24日 · 有2条记录`，不靠小点导航。 |
| 整月为空 | 够宽时仍画出安静格子 + 「这个月还没有留下什么。」窄到画不出 44pt 格子时只留空说明。 |
| 日子未确认 | 保留原入口，不放进某一天的格子。 |
| 最大字号 | `fontScale >= 1.3` 时不画七列月历，只保留纵向「有记录的日子」。 |
| 窄内容宽 | 用 `windowWidth − 安全区左右 − 页左右 24pt` 算七列。每格不到 44×44pt 时不画月历，只留「有记录的日子」。不缩小日期字、不压缩边距、不加不可见 hitSlop。 |
| 横屏 / iPad | 按实际内容宽判断，不按机型。够宽才画七列；iPad 不做成仪表盘。 |

不改：`occurredAt` 精度、个人 Moment、媒体保存、`/lookback/:year/:month/:day` 路由、回看滚动恢复。

## 状态对照

| 状态 | 真数据含义 | 月历 | 下方入口 |
| --- | --- | --- | --- |
| 无记录 | 该月 0 条 day 精度记录 | 全月安静格 | 无列表，中性空说明 |
| 稀疏 | 一两天有留下 | 对应格有痕迹 | 那一两天的可读行 |
| 密集 | 多天有留下 | 多格同权重痕迹 | 每一天一行，不按条数染色 |
| 同日多条 | 一天 3 条 | 一格 | 一行「有3条记录」 |
| 日子未确认 | `occurredAtPrecision=month` | 不占日格 | 原「日子未确认」入口 |
| 最大字号 | Dynamic Type 超大 | 不画七列，即使窗口够宽 | 只留纵向日期列表 |
| 窄内容宽 | 320pt 窗，或安全区吃掉宽度 | 不画七列 | 只留纵向日期列表 |
| 横屏 | 短高度 | 内容宽够才画七列 | 入口仍在 |
| iPad | 常规宽 | 阅读柱内，不拉满屏 | 同左 |

闰年：2024 年 2 月有 29 日且占周四起步的正确周位。2025 年 2 月没有 29 日。
