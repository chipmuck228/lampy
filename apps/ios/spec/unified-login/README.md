# Lampy 跨平台登录与找回

状态：已确认的产品方向；本 PR 已实施阶段 A 的身份底座与会话隔离，详见 [阶段 A](stage-a.md)。新增服务端迁移 34 和默认关闭的登录管理接口；不启用新登录渠道、不开放 Android 家庭入口、不改变 TestFlight 配置。阶段 B/C 尚未实施。

## 产品原则

- 一个人拥有稳定的 Lampy userId，可以绑定多种登录方式。家庭成员、共享记录作者和权限引用 userId，不引用手机号、邮箱或第三方昵称。
- 个人记录、个人册继续允许不登录使用；创建/加入家庭、访问服务端家庭内容时要求登录。
- 登录不代表个人本机记录已备份或同步。退出账号不删除个人记录，也不把本机记录自动上传或重新归属。
- 中国用户不必绑定邮箱，海外用户不必绑定手机号；备用方式建议添加，不在首次登录强制完成。
- 所有原生平台复用账号及服务端认证规则；客户端负责呈现与渠道授权，服务端负责验证、身份映射和 Lampy 会话。

## 渠道与展示

| 场景 | 默认主要入口 | 其他方式 |
| --- | --- | --- |
| 中国大陆 Android | 微信、手机号验证码 | 邮箱验证码、Apple 网页登录 |
| 中国大陆 iOS | 微信、Apple | 手机号验证码、邮箱验证码 |
| 海外 Android | Google | 邮箱验证码、Apple 网页登录；其他已开放渠道 |
| 海外 iOS | Apple、Google | 邮箱验证码；其他已开放渠道 |

这是默认排序，不是国籍判定或硬限制。发行渠道、设备能力、上次成功方式和用户主动选择共同决定显示；不能仅按语言/IP 隐藏用户原有的登录方式。主页面呈现两三个入口，其他入口放在“其他登录方式”。用户应能在支持的渠道中找回原账号。

渠道必须同时满足服务端已配置/启用、客户端具备集成能力、当前发行环境允许使用。失败不静默切换身份或自动新建第二个账号。中国基础登录流程不依赖 Google 服务；海外不依赖微信安装。未安装微信时给出可用替代方式。用户取消授权保持当前状态。

首版不做普通用户密码、Facebook/X、运营商一键登录或通行密钥；保留已有受控密码账号兼容，但不把测试账号开放成公开注册。

## 现有实现与需要补齐的边界

现有 Account/userId、LoginIdentity、Membership、Apple challenge 与显式绑定可复用。当前 LoginProvider、SQL CHECK 和内存/SQLite 仓储校验只支持 apple、controlled-password，不能只加客户端按钮或只修改 TypeScript 联合类型。

现有 Apple 登录禁止按邮箱自动合并账号，继续保留。现有受控邮箱密码流程不等于公开邮箱验证码登录。新的公开身份需要重新审查 session 准入：不能绕过冻结账号、受控账号禁用、删除状态等既有限制。

## 身份存储合同

下列为逻辑模型，具体表迁移在实施 PR 中提交，不直接覆盖既有 appleSubject 或修改历史迁移。

- Account：稳定 userId、创建时间、独立账号状态（后续不能用某个密码凭证状态代替整个账号状态）。
- LoginIdentity：provider、issuer/namespace、subject、userId、verifiedAt、createdAt；唯一键覆盖 provider + namespace + subject。
- 手机号：使用国家区号和规范化号码；身份可变、可换绑，绝不作为 userId。第一版只对实际已接通与验收的国家/地区开放发送。
- 邮箱：维护明确的规范化策略，不进行 Gmail 去点/加号截断等跨服务商猜测；可变邮箱不得作为 Google/Apple 的身份键。
- Google：服务端验证后的 issuer/sub；严格验证客户端 audience 白名单和有效期，不信任客户端传来的 email/userId。
- Apple：保持现有身份不变；Android 网页 Services ID 与 iOS App ID 的归组、audience 和 subject 映射必须用真实账号验证，不按相同邮箱跨端关联。
- 微信：服务端换取授权结果；OpenID 带 appId 范围存储，UnionID 带开放平台范围。只在服务端确认同一有效身份后建立别名映射；缺少 UnionID 不猜测跨应用合并。
- 持久层新增渠道时，内存与 SQLite 的约束行为一致；迁移可重复执行，失败回滚，不改既有 userId、家庭关系、分享归属或会话。

## 登录、绑定与解绑

1. “继续使用…”统一承载首次使用和再次登录。先完成凭证验证，再查身份；已有绑定进入原账号，没有绑定才在明确的登录流程中创建账号。
2. 添加登录方式只能从已登录账号发起，需要近期重新认证；挑战绑定当前 userId、session 与 intent，短期、一次性，取消/失败不修改绑定。
3. 身份已经属于另一个账号：返回冲突，不转移、不合并、不凭相同昵称/邮箱证明所有权。首版提供回到原账号的说明，不做自助账号合并。
4. 解绑需要近期验证，并保证至少保留一种可用登录方式。换绑手机号/邮箱需验证新目标；高风险场景需要另一项已绑定凭证或恢复流程，不能仅验证新号码。
5. 并发绑定、解绑、换绑必须事务化执行；唯一约束兜底，避免“检查后写入”竞态。
6. 邮箱/短信验证挑战区分 login/link/change/recovery，限制目标、尝试次数、时效、重发间隔和使用次数；验证码不能跨用途使用。

## 账号找回

“登录与找回”展示脱敏的已绑定方式，允许增加备用方式、换绑、查看设备会话和退出其他设备。创建家庭/成为创建者或跨设备使用时温和提醒备用方式。

失去一个渠道时使用另一项已绑定方式进入同一个 userId。恢复码可作为后续独立阶段，服务端仅保存摘要，一次使用，重新生成使旧码失效；未实施前不能宣称提供。

全部凭证丢失时不得凭家庭名称、邀请、昵称、亲属关系恢复账号。首版没有可靠证据的情况明确不承诺恢复，不开放客服随意改绑。家庭创建者不能修改成员的登录方式。手机号回收/SIM 更换需纳入风险策略，短信不是所有高风险操作的唯一验证手段。

账号删除、退出家庭、退出登录是三个不同操作。已有 Apple 删除/撤销能力不能因新增渠道退化；后续逐渠道定义注销和授权撤销要求。

## 会话与设备隔离

- 第三方 token/code 只用于验证，不直接作为家庭 API 会话；凭证秘密仅在服务端保存，日志不记录 token/验证码/完整号码。
- 沿用并加强 Lampy 会话；会话续期、撤销、设备列表和近期认证分开建模。长期凭证存系统安全存储。
- 切换账号递增身份代次，取消旧请求/上传/下载，清除旧账号家庭 UI 状态；异步结果提交前再次检查 userId 与代次。
- 家庭缓存和待处理任务按 userId 隔离；退出后不能残留可见的前账号家庭内容。个人本机记录保持现有保全语义。
- 登录不接受家庭邀请。邀请预览 → 登录 → 返回原邀请 → 显式确认加入；邀请只授予对应家庭成员资格，不授予账号所有权。

## 服务与运营准备

- 微信：开放平台移动应用资质、iOS/Android 标识与签名配置、SDK/回调、AppSecret 服务端保管；真实授权与取消返回。
- Google：两端 OAuth 客户端、签名指纹、服务端 audience 列表；Android Credential Manager、iOS 官方 SDK；真实账号跨端验证。
- Apple：保留原生 iOS 流程，补充 Android 系统浏览器网页授权与安全回跳；Services ID/主 App ID/回调域名与实际身份一致性验证。
- 短信：签名/模板/服务商审核、发送国家白名单、费用预算、设备/IP/号码/全局限流、异常告警。供应商切换不能重置验证码挑战或绕过限额。
- 邮件：发件域名和送达配置；优先验证码，减少跨 App 魔法链接处理复杂度。发送成功不当作验证成功。
- 不据语言自动划分数据存储区域。地区部署、跨区家庭与数据存放在开放相应市场前单独确认，不能无意建立互不相通的账号孤岛。

## 分阶段 PR 与完成标准

| 阶段 | 实施内容 | 验收门槛 |
| --- | --- | --- |
| A | 通用身份与迁移、账号状态、绑定冲突与最后凭证保护、会话/缓存隔离 | 历史账号不变；并发约束、重放、冻结账号、账号切换测试通过；新渠道默认关闭 |
| B1 | 手机号/邮箱验证码的发送与验证闭环、双端页面 | 真实送达、错误/过期/重发/限流/预算、绑定换绑与找回验证；未配置时不露入口 |
| B2 | 微信、Google、Android Apple 网页登录 | 两端真实授权/取消/失败；同账号跨端、绑定冲突与卸载重装验证 |
| C | Android 家庭入口及跨端家庭相册 | iOS/Android 双账号双设备邀请、共享、媒体、退出/移除/撤销权限通过后开放 |

先完成 A，再提交各渠道实现，避免一个 PR 同时修改身份底座、多个外部 SDK 和家庭权限。测试替身不等于真实渠道验收。登录能力完成也不代表家庭功能可直接发布。

### 必须覆盖的端到端情况

- Apple 老账号升级后仍是原 userId 和原家庭；Android 通过已绑定微信/Google/手机号或 Apple 网页进入原账号。
- 同邮箱的 Apple/Google 与独立邮箱账号不自动合并；同昵称微信账号不合并。
- 被其他账号占用的绑定、最后凭证解绑、并发换绑、验证码重放、取消授权均不改变已有身份。
- 号码丢失、渠道失效、会话到期、网络断开均有明确恢复路径，不把认证失败显示为“家庭为空”。
- 邀请跨登录返回后仍需确认，过期/撤销邀请无法加入。
- A 用户退出，B 用户登录，A 的响应、家庭相册、媒体及后台上传不进入 B 的视图。
- 个人记录/个人册在不登录、退出账号和升级后保持完整；设备本机保护与云端登录分别验收。

## 发布隔离

本 PR 不接入真实渠道 SDK、不部署 API、不操作线上数据库、不改变 iOS Bundle ID/签名/构建号、不上传 TestFlight。阶段 A 包含待部署的迁移 34，部署步骤见阶段文档。实现独立于个人册 PR；新渠道服务端与客户端均默认关闭，凭证和真机验收齐备后再逐步开放。
